Accessibility Statement

Accessibility is a product requirement, not a badge.

Target Media aims to make this website usable with keyboards, screen readers, reduced-motion settings and common assistive technologies. This is a practical target, not a claim of formal certification.

Last updated: 11 September 2026

1. Current accessibility measures

  • A “Skip to main content” link is available for keyboard users.
  • Visible focus indicators are provided for links, buttons and form controls.
  • The mobile navigation button has an accessible label and exposes its expanded/collapsed state.
  • FAQ controls use buttons and update aria-expanded.
  • The dedicated Monitor application page uses native labelled form controls and button-based date/time selection that can be reached by keyboard.
  • Form controls have explicit labels and supporting instructions.
  • Button labels describe the action, for example “Apply for Monitor”, “Submit Monitor application” and “Verify code”.
  • The illustrative chart has a text alternative that states the sample values and that they are illustrative.
  • Decorative SVG graphics are hidden from assistive technology where appropriate.
  • Small and secondary text colours were increased in contrast against the dark background.
  • Users who prefer reduced motion are served a reduced-motion version.
  • No autoplaying video or audio is present.

2. Images and alternative text

The current site contains no photographic content. The Target Media logo is accompanied by the brand name in text and decorative SVG elements are hidden from screen readers where they do not add information. If meaningful images are added later, they must receive concise, purpose-specific alt text; decorative images should use empty alt text or be hidden appropriately.

3. Colour contrast

The current build uses light foreground text against a near-black background and avoids using low-contrast grey for essential small text. Colour is not intended to be the only way important information is communicated.

Formal WCAG contrast testing should still be part of any production QA process, especially after brand or component colours change.

4. Conformance target

Our target is to follow the principles of WCAG 2.2 Level AA where practical. This statement does not claim that an independent accessibility audit has certified full conformance.

5. Known limitations and future review

No known critical keyboard blocker is intentionally present in the current static build. However, new dashboards, charts, authentication, payment flows, video, maps or third-party widgets can introduce accessibility issues and must be re-tested before launch.

A production accessibility review should include keyboard-only testing, screen-reader testing, zoom/reflow, colour-contrast checks, error-message behaviour and mobile touch targets.

6. Dutch/EU context

Dutch guidance implementing the European Accessibility Act applies accessibility requirements to certain consumer-facing products and services, including relevant e-commerce services, subject to scope and exemptions. Target Media currently presents this as a B2B Monitor application flow; the payment step is not yet active. Accessibility remains a design requirement even where the EAA may not apply to the present flow.

Official reference: Business.gov.nl — accessibility rules (EAA).

7. Feedback

The final production site should publish a working accessibility contact channel. The repository does not yet contain the company’s confirmed email/phone details, so no contact information is invented here.
